# CosmetCheck 免费额度用户激活断点审核任务书

> 发布者：CTO  
> 接收者：@Hermes_chanpin_bot（产品 Agent）  
> 任务类型：产品流程审核 / 用户体验诊症  
> 期望交付：审核报告 + 改进建议清单

---

## 一、任务背景

CosmetCheck 当前的免费额度策略为：
- **无需注册**，IP 级别识别
- **10 次检测 / 30 天**
- 超过后提示升级 Pro（`/pricing`）

但当前存在一个核心疑问：**用户从首次进站到完成第一次检测，再到消耗完免费额度转化付费，这条路上有多少激活断点？**

本任务要求产品 Agent 作为"第一个用户"，从产品视角对全流程进行遐步检查，识别每一个可能导致用户流失的断点。

---

## 二、免费额度机制详情（代码层）

### 配额逻辑
- 文件：`src/lib/quota.ts`
- 存储：Supabase `user_quotas`表（`identifier`, `count`, `reset_at`）
- 识别方式：IP 地址（`x-forwarded-for`、`x-real-ip`）
- 重置周期：30 天
- 超限提示：`"You have used X of 10 free checks. Please upgrade to Pro for unlimited access."`
- 白名单：环境变量 `QUOTA_WHITELIST` 控制

### 认证与订阅
- 未登录用户：仅能使用检测（`/api/check`），不能生成 Listing（`/api/generate`返回 403）
- 登录用户（Free）：仍受 10 次/30天配额限制（但可以保存历史记录）
- Pro 用户：无限检测 + 无限生成 + 客服机器人

### 速率限制
- 检测：30 req/min
- 生成：10 req/min（token bucket，持久化在 `rate_limits` 表）
- 批量：5 req/min

## 三、需要审核的用户旅程

请按以下阶段，逐步审查每个触点的用户体验和激活断点。

### 阶段 1：首次进站 → 产生检测意愿

**URL**：`https://cosmetcheck.pages.dev`（或本地 `http://localhost:3000`）

**审核要点**：
- [ ] HeroSection 标题和副标题是否让目标用户（拉美美妆卖家）立刻明白"这是什么"和"能解决什么问题"？
- [ ] 社会证明元素（已服务卖家数、风险阻止数、平台覆盖）是否足够强？
- [ ] 首屏检测表单的 CTA 是否清晰？"免费检测"的心智模型是否一眼可见？
- [ ] 语言切换器是否容易发现？目标用户（PT/ES）是否会在首屏看到母语？
- [ ] 移动端体验：表单输入是否方便？按钮是否足够大？
- [ ] 页面加载速度是否过慢？（特别是 Edge Runtime 冷启动）
- [ ] 是否有排除用户的因素？（如验证码、强制注册、复杂的国家选择流程）

**请特别关注的断点**：
- 用户看到首页后 3 秒内是否知道"该做什么"？
- 如果用户不会英语，能否在首屏切换到 PT/ES 而不是默认的 EN？
- 首屏是否存在过多内容导致"分心"＜用户没有快速找到检测入口？

### 阶段 2：检测表单填写 → 提交

**审核要点**：
- [ ] 成分输入框的 placeholder 是否清晰易懂？（支持中英文输入，但 placeholder 是英文）
- [ ] 国家选择（BR/MX）是否直观？用户是否有困惑？
- [ ] 产品描述/标签字段是否让用户觉得"复杂"？（实际上这两个字段是可选的）
- [ ] "Check Now" 按钮的可见性和点击意愿
- [ ] 是否有进度提示或 loading 状态？（检测过程可能需要 1-3 秒）
- [ ] 如果用户输入了无效内容，错误提示是否友好？

**请特别关注的断点**：
- 用户是否知道"成分"vs"描述"vs"标签"的区别？会不会因为不知道该填哪个而放弃？
- 用户输入中文成分名（如"水、甘油、烟酰胺"），引擎能否正确解析？（支持但用户未必知道）
- 移动端文本输入是否有障碍？（键盘占据、textarea 高度）

### 阶段 3：等待检测结果 → 结果页展示

**审核要点**：
- [ ] Loading 状态是否有趣不无聊？（当前只是简单的 spinner）
- [ ] 检测结果的可读性：违规项是否分类清晰（critical/warning/info）？
- [ ] 规则来源是否展示（ANVISA RDC 529/2021 等）？是否增加了可信度？
- [ ] 修改建议是否具体可执行？
- [ ] 结果页是否有后续行动指引？（如"生成合规 Listing"、"保存结果"、"分享"）
- [ ] 结果页是否展示剩余免费次数？（重要：让用户知道还能用多少次）

**请特别关注的断点**：
- 检测失败时（API 500/429）的错误提示是否让用户有勇气重试？
- 如果结果是"全部合规"，用户是否知道下一步该做什么？（可能直接关页走人）
- 结果页上的"AI Generate Listing"按钮，未登录用户点击后会发生什么？（弹出登录框 vs 直接跳转 pricing 页）

### 阶段 4：第一次检测后 → 第二次/多次检测

**审核要点**：
- [ ] 第一次检测结束后，页面是否方便地进行第二次检测？（是否需要刷新页面？）
- [ ] 是否有"检测历史"或"最近检测"功能促使复用？（当前未登录用户无此功能）
- [ ] 剩余次数提示是否可见且不刺眼？
- [ ] 当用户用完第 5 次左右时，是否有"您已使用一半额度"的温和提示？

**请特别关注的断点**：
- 用户是否需要每次都重新输入所有信息？没有"保存产品信息"功能导致复检繁琐？
- 多次检测后，结果页是否保持新鲜感，还是用户已经"习惯"了？

### 阶段 5：额度消耗中后期 → 付费转化

**审核要点**：
- [ ] 当用户用完第 7-8 次时，系统是否有提醒？（如"还剩 3 次，升级 Pro 无限检测"）
- [ ] 额度耗尽时（429 错误）的提示是否友好？是否直接引导到付费页？
- [ ] 付费页的转化设计：
  - 月付/年付切换是否易用？
  - 年付优惠信息（省多少）是否突出？
  - 信任指标（退款承诺、安全徽章、用户数量）是否充足？
  - Stripe/PayPal 支付流程是否顺畅？
- [ ] 从"额度耗尽提示"到"完成付费"的步骤是否过多？

**请特别关注的断点**：
- 用户在检测过程中弹出"升级 Pro"，是否会打断当前检测流程？
- 当用户看到价格时，是否立即知道"这个价格值不值"？
- 是否有弹窗或回退机制催化转化？（如限时优惠、注册送额外次数）

### 阶段 6：注册流程本身

**审核要点**：
- [ ] AuthModal 的开启触发点是否自然？（当用户点击"生成 Listing"时弹出）
- [ ] 注册表单的字段是否过多？（当前只需邮箱+密码）
- [ ] 是否支持社交登录？（当前不支持，需要注册是否拟增加障碍？）
- [ ] 注册后是否自动回到原来的操作？（如生成 Listing）
- [ ] 验证邮箱是否必须？（当前不需要，可能导致虚假用户）
- [ ] 忘记密码流程是否完整？

**请特别关注的断点**：
- 用户在检测结果页被强制要求登录时，是否会选择"放弃"而不是"登录"？
- 注册密码的强度要求是否过高导致转化下降？

## 四、辅助功能断点

### ChatWidget（右下角悬浮窗）
- [ ] 免费用户点击 ChatWidget 时，是否明确告知"需要登录"？
- [ ] 支持和顾问模式的区别是否让用户感到困惑？
- [ ] 未登录用户是否误以为可以免费使用 AI 客服？

### 语言切换
- [ ] 非英语用户是否能顺利切换语言？
- [ ] 切换语言后结果页的规则来源是否也被正确翻译？

### 批量检测入口
- [ ] 免费/月付用户访问 `/batch` 时，提示是否清晰？（"需要年付 Pro"）
- [ ] 是否有升级引导，还是只是简单拦截？

## 五、交付物要求

请产出一份 **《免费额度用户激活断点审核报告》**，包含：

### 1. 用户旅程地图（User Journey Map）
- 横轴：进站 → 理解价值 → 填写表单 → 检测 → 查看结果 → 复检 → 额度提示 → 付费/注册
- 纵轴：情感曲线、关键行动、隐形障碍

### 2. 断点清单（Drop-off Points）
对每个断点标注：
- **位置**：哪个页面/组件
- **问题描述**：具体是什么问题
- **影响程度**：高/中/低（估算对转化率的影响）
- **修复建议**：具体可执行的产品改进方案
- **优先级**：P0 / P1 / P2

### 3. 数据埋点需求
列出需要运营/研发配合补充的事件埋点（如转化漏斗、界面点击热图等）

### 4. A/B 测试建议
基于断点分析，提出可验证的优化假设

## 六、审核方式

1. **本地走查**：在本地起动项目（`npm run dev`），以"第一次访问的拉美美妆卖家"视角模拟完整流程
2. **混淆测试**：尝试用各种"乱用"方式打破流程（空输入、随便点击、中途刷新、切换语言）
3. **移动端测试**：使用 Chrome DevTools 模拟手机视角进行上述流程
4. **多语言测试**：切换到 pt-BR / es-MX / zh，检查语言体验是否一致
