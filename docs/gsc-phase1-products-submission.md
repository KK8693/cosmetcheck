## 三、提交操作 SOP

### 手动提交步骤

1. 登录 Google Search Console: https://search.google.com/search-console
2. 选择属性: `cosmetcheck.com`
3. 左侧导航 → **编制索引** → **网页**
4. 在输入框中粘贴 URL（上方清单中的完整 URL）
5. 点击 **请求编入索引**
6. 等待 GSC 验证结果（通常 10-30 秒）
7. 确认状态显示为 **"已提交"** 或 **"已引入"**

### 提交记录模板

在提交时记录以下信息，用于 48h 后跟踪：

```
日期: 2026-06-XX
提交人: 运营经理
URL: https://cosmetcheck.com/products/XXX/brazil
GSC 状态: 已提交 / 已引入
备注:
```

### 注意事项

- 每个 URL 只需提交一次，重复提交不会加快索引速度
- 若 GSC 提示 **"已引入"**，表示 Google 已知道该 URL，无需重复提交
- 若 GSC 提示 **"未能引入"**，检查页面是否有 noindex 标签或 robots.txt 阻止
- 每日提交上限约 10 个，超出可能被限制

## 四、48h 跟踪检查清单

在首次提交后 48 小时内，检查以下指标：

### GSC 状态检查
- [ ] 提交的 URL 是否出现在 **"已引入"** 状态
- [ ] 是否有 URL 显示 **"未能引入"** 或 **"已发现 - 当前未引入"**
- [ ] 是否有 URL 显示 **"抓取错误"**（如 404、500等）

### 技术检查
- [ ] 检查 GSC 的 **"覆盖范围"** 报告，确认 products 页面被抓取
- [ ] 检查 **"网页体验"** 报告，确认无新的 404 或重定向错误
- [ ] 验证 robots.txt 未阻止 `/products/*` 路径

### 问题处理
若发现问题，按以下流程处理：

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| 404 | 页面未部署或路径错误 | 检查 Vercel/Cloudflare 部署状态，确认路由存在 |
| 重定向循环 | 中间件或路由配置错误 | 检查 next.config.js 和中间件重定向规则 |
| 抓取错误 | 服务器返回 500 | 检查日志，确认数据源是否正常加载 |
| 未引入 | 质量问题或抓取预算不足 | 确保内容质量，等待自然抓取，或通过内部链接引导 |
